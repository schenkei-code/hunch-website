Loslegen

Hunch ist eine persönliche Agent-Runtime für PC, Mac und VPS. Drei Befehle, dann läuft sie.

Installation

pipx install .          # oder: pip install .

hunch init              # Ordner anlegen, zeigen was fehlt
hunch check             # Antworten die Modelle? Was liegt hier?
hunch run               # läuft, auf 127.0.0.1:8000

hunch check endet mit Exit-Code 1, wenn etwas nicht antwortet — taugt also für ein Startskript oder eine Überwachung, ohne dass jemand die Ausgabe liest.

Auf dem Server (systemd)

sudo cp deploy/hunch.service /etc/systemd/system/
sudo systemctl enable --now hunch
journalctl -u hunch -f

Die Unit läuft als eigener Nutzer und bindet auf 0.0.0.0 — deshalb braucht sie ein HUNCH_AUTH_TOKEN in ~/.hunch/env, sonst startet sie nicht. Schlüssel gehören in diese Datei (0600), nicht in die Unit: die steht im Klartext in /etc/systemd und wandert in jedes Backup.

Ohne gemieteten Server

Ein Rechner, der ohnehin läuft, reicht — und das Telefon erreicht ihn von unterwegs über ein privates Netz zwischen den eigenen Geräten (Tailscale, WireGuard). Kein Port im Router, keine feste Adresse, alles verschlüsselt.

Dabei an die Adresse aus diesem Netz binden, nicht an 0.0.0.0:

HUNCH_HOST=100.101.102.103 HUNCH_AUTH_TOKEN=… hunch run

Der Unterschied ist nicht kosmetisch. 0.0.0.0 heißt: auch das Gäste-WLAN, auch ein Router, der irgendwann einen Port weiterleitet. Die Tailscale-Adresse heißt: nur die eigenen Geräte.

Windows

.\deploy\hunch-windows.ps1              # einrichten, startet bei der Anmeldung
.\deploy\hunch-windows.ps1 -Starten     # sofort loslegen
.\deploy\hunch-windows.ps1 -Zeigen      # Zustand ansehen

Ohne Administratorrechte, unter deinem Konto — eine Runtime unter SYSTEM hätte keinen Zugriff auf deine Dateien. Die geplante Aufgabe liest ~/.hunch/env ein und läuft bei einem Absturz bis zu dreimal wieder an.

HTTPS — und warum das iPhone sonst nicht mitspielt

Wer die Runtime über Tailscale erreichen will, braucht ein Zertifikat. Nicht aus Prinzip, sondern weil iOS sonst gar nicht erst anfragt: App Transport Security erlaubt Klartext-HTTP nur ins wirklich lokale Netz — 192.168.*, 10.*, *.local. Eine Tailscale-Adresse liegt in 100.64.0.0/10 und zählt dort nicht dazu.

tailscale cert --cert-file ~/.hunch/tls/hunch.crt \
               --key-file  ~/.hunch/tls/hunch.key \
               dein-rechner.tailXXXX.ts.net

Dann die beiden Pfade in HUNCH_TLS_CERT und HUNCH_TLS_KEY, und in der App den Namen eintragen, nicht die IP — ein Zertifikat gilt für einen Namen. Auf einem VPS hinter einem Reverse-Proxy bleiben beide Variablen leer: dort macht der Proxy das TLS.

Direkt am Gedächtnis, ohne Server

hunch remember "Steuerunterlagen bis Ende März einreichen"
hunch search Steuer
hunch tasks

Das ist dasselbe Gedächtnis, das die App und Claude Code sehen — kein Export, kein Abgleich.
