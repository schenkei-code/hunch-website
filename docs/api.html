HTTP-API

Die Runtime spricht HTTP und WebSocket auf 127.0.0.1:8000 (konfigurierbar). Alles hinter dem Auth-Token, sobald sie nicht auf localhost lauscht.

Endpunkte

WegWofür
POST /eventsEreignis melden
GET /nudges?since=Impulse abholen
GET /approvals · POST /approvals/{id}Freigaben sehen und beantworten
POST /brain/syncGedächtnis abgleichen, beide Richtungen
GET /brain/search?q=Im Gedächtnis suchen
GET /tools · GET /audit · GET /statusNachsehen, was da ist und was war
GET /providers · GET /runtimesWelche Modelle und welche Agenten hier gehen
GET /v1/channelsWas diese Runtime mitliest, im Klartext
GET /v1/wallet · POST /v1/wallet-passOb eine Wallet-Karte geht, und sie bauen
WS /wsEreignisse rein, Impulse raus — ohne Abfragen

Ein Ereignis von Hand

curl -X POST localhost:8000/events \
  -H 'Content-Type: application/json' \
  -d '{"source":"cli","kind":"user_message","payload":{"text":"was steht an?"}}'

curl localhost:8000/nudges

Status und Provider

GET /providers liefert die Anbieter-Liste, GET /status sagt, ob beide Rollen tatsächlich antworten — Schlüssel dabei immer nur als Ja/Nein.
