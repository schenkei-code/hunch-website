Dokumentation

HTTP-API

HTTP und WebSocket auf 127.0.0.1:8000. Alles hinter dem Token, sobald nicht auf localhost. Dokumentiert sind nur real existierende Routes.

Identität & Einlass

GET  /v1/identity                 POST /v1/identity/enroll
POST /v1/identity/challenge       POST /v1/identity/verify
POST /v1/identity/grant           DELETE /v1/identity/grant/{scope}
POST /v1/einlass/erzeugen         POST /v1/einlass

Fäden & Approvals

GET /faeden      GET /faeden/{id}      POST /faeden      DELETE /faeden/{id}
GET /approvals   POST /approvals/{id}   GET /proposals    POST /approve  POST /deny

Konsole & Ausführung

POST /v1/konsole   POST /v1/konsole/freigabe   GET /v1/konsole/{id}   POST /v1/exec

Kanäle

GET /v1/channels                 POST /v1/channels/telegram
POST /v1/channels/whatsapp       GET  /v1/channels/whatsapp/qr
POST /v1/channels/{id}/test      DELETE /v1/channels/{id}

Gedächtnis, Aufgaben, Vorhersage

POST /brain/sync   GET /brain/search?q=   GET /v1/intents
POST /sitzung      GET /vorhersage

Rechenschaft: Rückweg & Grenze

GET /rueckweg            POST /rueckweg/{id}      (Undo: Erinnerung/Aufgabe zurücknehmen)
GET /grenze              (was Hunch nie ohne Rückfrage tut)

Werkzeuge, Audit, Status

GET /tools   GET /audit   GET /status
GET /providers   GET /runtimes   GET /v1/machine

Vault, Wallet

GET /v1/vault   POST /v1/vault/setup   GET /v1/vault/envelope
POST /v1/vault/unlock   POST /v1/vault/unlock-code   POST /v1/vault/lock
GET /v1/wallet   POST /v1/wallet-pass

Ereignisse, Push, Stream

POST /events   POST /v1/events   GET /nudges?since=
POST /v1/push-token   GET /v1/push
WS /ws   WS /v1/ws   GET /v1/stream   (SSE-Fallback)

MCP hat keinen HTTP-Endpoint — der Server läuft über stdio (python -m hunch_runtime.mcp_server). Ein Ereignis von Hand:

curl -X POST localhost:8000/events -H 'Content-Type: application/json' \
  -d '{"source":"cli","kind":"user_message","payload":{"text":"was steht an?"}}'
curl localhost:8000/nudges
