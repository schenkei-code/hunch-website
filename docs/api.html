HTTP-API

Im Betrieb lauscht die Runtime über HTTPS in deinem privaten Tailnet; 127.0.0.1:8000 ist nur die lokale Entwicklungs-Vorgabe. Authentifizierung ist absichtlich pro Route abgestuft: geschützte Maschinenzugriffe können den Bearer-Token nutzen, personenbezogene Besitzerflächen werden über den Ausweis-Nachweis freigegeben — der Master-Token ist dafür kein Ersatz. POST /v1/einlass ist bewusst tokenfrei — der einmalige Code ist die Berechtigung, begrenzt auf fünf Versuche pro 15 Minuten.

Diese Seite zeigt ausgewählte reale Routen, kein Live-Inventar. Lokale Introspektion des aktuellen Source erzeugt 108 OpenAPI-Pfade; hinzu kommen interne Web-/Doku-Flächen und drei WebSockets. Das Schema der laufenden Runtime war bei der Prüfung nicht abrufbar.

MCP hat keinen HTTP-Endpoint — der Server läuft über stdio (python -m hunch_runtime.mcp_server). Ein Ereignis von Hand, nur in einer lokalen Entwicklungs-Konfiguration ohne Auth:

curl -X POST http://127.0.0.1:8000/events -H 'Content-Type: application/json' \
  -d '{"source":"cli","kind":"user_message","payload":{"text":"was steht an?"}}'
curl http://127.0.0.1:8000/nudges

Für die private Runtime dieselben Routen über ihre HTTPS-Adresse aufrufen und bei token-geschützten Routen Authorization: Bearer <TOKEN> mitsenden. Besitzerflächen wie /graph und /muster bleiben hinter dem Ausweis; der Master-Token ersetzt ihn nicht.
