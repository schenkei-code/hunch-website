Ohne Token auf einer öffentlichen Adresse startet die Runtime nicht. Das ist kein Komfortverlust, sondern der Unterschied zwischen deinem Agenten und dem Agenten von irgendwem.

Welches Modell (auto)

Die Vorgabe ist auto, und die Runtime entscheidet selbst. hunch init sagt, wie sie entschieden hat und warum.

Für die Executive zählt zuerst ein Schlüssel, der ohnehin in der Umgebung steht, dann ein Kommandozeilenwerkzeug, das hier liegt, dann ein laufender lokaler Server.

Der Observer läuft dauernd und wird deshalb anders gewählt: zuerst ein lokaler Server — wobei wirklich am Port nachgefragt wird —, dann ein Anbieter, für den ein kleines Modell hinterlegt ist. Eine CLI wird nie automatisch zum Observer. Bleibt nichts übrig, läuft die Runtime ohne Observer: sie bemerkt dann nichts von selbst, antwortet aber auf direkte Ansprache.

Anbieter

Beide Rollen nehmen jeden Anbieter — dieselbe Liste wie das Hauptmodell in der App: claude, openai, gemini, kimi, deepseek, qwen, mistral, grok, groq, dazu die lokalen ollama, lmstudio, llamacpp. Ein eigener Endpunkt geht auch: beliebige ID plus HUNCH_*_BASE_URL.

Ohne Schlüssel: die CLI-Provider

claude-cli, codex-cli und gemini-cli benutzen die Kommandozeilenwerkzeuge, die schon auf dem Rechner liegen. Wer dort angemeldet ist, zahlt bereits ein Abo — einen API-Schlüssel zusätzlich zu verlangen hieße, dasselbe Modell zweimal zu bezahlen.

HUNCH_EXECUTIVE_PROVIDER=claude-cli hunch run
HUNCH_EXECUTIVE_PROVIDER=cli:antigravity hunch run
HUNCH_EXECUTIVE_PROVIDER="cli:meintool --headless" hunch run

Ein Aufruf startet ein Programm und dauert einige Sekunden. Als Executive richtig — sie läuft selten. Als Observer zu langsam; dafür lieber ein kleines Modell über HTTP.

Schlüssel

Die Runtime sucht selbst: erst HUNCH_OBSERVER_API_KEY bzw. HUNCH_EXECUTIVE_API_KEY, dann HUNCH_KEY_<ANBIETER>, dann was der Anbieter üblicherweise setzt (ANTHROPIC_API_KEY, OPENAI_API_KEY, …).
