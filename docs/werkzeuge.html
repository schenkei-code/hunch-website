Werkzeuge & Skills

Vier Herkünfte, ein Verzeichnis — die Executive sieht keinen Unterschied, woher ein Werkzeug kommt. Skills und Werkzeuge sind nicht an den Modellprovider gebunden.

Eingebaut Heute

search_memory, remember, list_tasks, add_task, run_command (kritisch), http_get. Dazu bedingte Bündel: Chat-Tools (wenn ein Kanal verbunden ist), Reach-Tools (youtube_lesen, github_lesen, reddit_lesen, rss_lesen, netz_suchen) und der Browser (web_ansehen).

Skills Heute

  • SKILL.md — eine Anleitung für das Modell (Prosa)
  • Python-Dateien mit run(arguments) — werden ausgeführt

Ort: HUNCH_SKILLS_DIR (Vorgabe ./skills).

MCP Heute

Werkzeuge fremder Server aus mcp_config.json, dynamisch geladen. Umgekehrt bietet Hunch selbst einen MCP-Server (stdio) an — siehe Gedächtnis.

REST-Connectoren Heute

Schnittstellen aus connectors.json — ohne eine Zeile Code.

Externe Agent-Harnesses Heute

Eingebaut: Codex, Claude Code, Gemini CLI, Aider. Eigene über ~/.hunch/harnesses.json. Für das Modell ist das ein Werkzeug run_agent, immer als kritisch eingestuft — ein fremder Agent bringt seine eigene Loop mit und hängt nicht am Governor dieser Runtime; die Freigabe vor dem Start ist die Kontrolle. Positivliste für Umgebungsvariablen, Zeitgrenze und gekappte Ausgabe schützen zusätzlich.

Kompatibilität — ehrlich Als Nächstes

Jeder Anbieter kann angebunden werden, wenn Modell oder Werkzeug über einen unterstützten Standard oder Adapter erreichbar ist (MCP, Function-Schemas, Markdown/Python-Skills, REST, Harnesses). Ein proprietäres Plugin-Paket kann einen Adapter benötigen. Nicht jedes Plugin jedes Anbieters funktioniert automatisch.
